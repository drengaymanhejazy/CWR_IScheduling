# معمارية طبقة الإنتاج والتسويق

## 1. الهدف

تضيف هذه الطبقة سجلًا تشغيليًا للإنتاج والتسويق فوق طبقات الطقس والمحصول والري والتسميد. لا تستبدل الطبقات الحالية ولا تعيد حساب `ET0` أو `Kc` أو `ETc`، بل تستخدم مخرجاتها لتفسير الإنتاجية والتكلفة والعائد.

الهدف هو الانتقال من:

```text
احتياج مائي وسمادي تقديري
```

إلى:

```text
خطة إنتاج → عمليات ومدخلات فعلية → إنتاج وفرز → بيع وتسويق → تكلفة وعائد
```

## 2. المبادئ المعمارية

1. **الحقل والموسم هما محور البيانات**: كل إنتاج أو تكلفة أو عملية أو بيع يجب أن يرتبط بحقل وموسم ومحصول.
2. **التقديري منفصل عن الفعلي**: لا نخلط التكاليف المخططة مع الفواتير أو الكميات المنفذة.
3. **سجل الأحداث غير قابل للالتباس**: الري والتسميد والعمل والرش والحصاد والنقل تسجل كأحداث مؤرخة.
4. **الوحدة إلزامية**: كل كمية أو سعر أو تكلفة يحمل وحدة ومرجع تحويل عند الحاجة.
5. **العملة والزمن محفوظان**: السعر يسجل مع العملة وتاريخ السعر ومصدره، لأن المقارنة بين أسعار مختلفة الزمن دون هذا الحفظ مضللة.
6. **الدفعة التسويقية قابلة للتتبع**: الإنتاج قد يفرز إلى درجات ودفعات، وكل دفعة ترتبط بحصاد وبيع أو مخزون.
7. **لا توصية سعرية مصطنعة**: السعر السوقي يقرأ من إدخال المستخدم أو مصدر موثق، ولا يخترع عند غيابه.
8. **التقديرات قابلة للاستبدال**: يمكن استبدال الإنتاج المتوقع بالإنتاج الفعلي عند الحصاد دون حذف التقدير السابق.

## 3. المعمارية المنطقية

```text
              │   ├── ميزان الماء والري الفعلي
              │   └── التوصية السمادية وسجل الإضافة
              │
              ├── سجل العمليات والمدخلات

              │   ├── طاقة ومياه
              │   ├── أسمدة ومبيدات
              │   ├── خدمة وآلات
              │   └── نقل وتعبئة
              │
              ├── الإنتاج
              │   ├── توقع الإنتاج
              │   ├── حصاد فعلي
              │   ├── فرز وجودة
              │   └── مخزون/فاقد

```

## 4. الكيانات الأساسية

### 4.1 الحقل والموسم

تستخدم الطبقة الحالية `field` و`season_start` و`crop_id`. في طبقة قاعدة البيانات المستقبلية يجب تثبيت معرفات مستقرة:

- `field_id`: معرف الحقل.
- `season_id`: موسم زراعي مستقل حتى لو تكرر المحصول في الحقل نفسه.
- `crop_id`: معرف قاعدة المحاصيل المحلية.
- `area_value` و`area_unit`: المساحة ووحدتها.
- `irrigation_mode`: مروي أو بعل.
- `status`: مخطط، قائم، محصود، مغلق.

### 4.2 خطة الإنتاج

تحفظ افتراضات ما قبل الموسم دون اعتبارها حقيقة:

- الإنتاجية المستهدفة لكل وحدة مساحة.
- الإنتاج المتوقع الكلي.
- تاريخ أول حصاد وآخر حصاد متوقع.
- نسبة الجودة أو الفرز المتوقعة.
- نسبة الفاقد المتوقعة.
- مصدر الافتراض: المستخدم، مرشد، جدول محلي، أو تاريخ الحقل.

### 4.3 سجل العمليات والمدخلات

بدل إنشاء جدول منفصل لكل نوع تكلفة، يستخدم النموذج سجلًا موحدًا مع تصنيف واضح:

- `operation_type`: حراثة، زراعة، ري، تسميد، رش، تعشيب، حصاد، فرز، تعبئة، نقل، تخزين.
- `input_type`: ماء، طاقة، سماد، مبيد، بذار، شتول، عمالة، آلة، عبوة، نقل، خدمة.
- `planned_or_actual`: مخطط أو فعلي.
- الكمية والوحدة والسعر الوحدي والعملة.
- تاريخ التنفيذ أو تاريخ الاستحقاق.
- مصدر السعر أو رقم الفاتورة.

هذا التصميم يسمح بربط تكلفة السماد بما خرج من محرك التوصية وما أضيف فعليًا، دون خلط الاثنين.

### 4.4 الإنتاج والحصاد

يجب عدم تخزين «إنتاج الموسم» كرقم واحد فقط. النموذج يسجل:

- عملية حصاد بتاريخ محدد.
- الكمية الخام.
- الوحدة.
- الدفعة أو المنطقة داخل الحقل عند توفرها.
- الكمية القابلة للتسويق.
- الفاقد.
- ملاحظات الجودة.

### 4.5 الفرز والجودة

كل دفعة حصاد يمكن أن تنتج عدة سجلات فرز:

- الدرجة: ممتازة، أولى، ثانية، تصنيع، مرفوضة.
- الكمية.
- الوحدة.
- سبب التخفيض أو الرفض.
- رطوبة أو حجم أو مواصفة نوعية عند الحاجة.

### 4.6 السوق والسعر

السعر ليس خاصية ثابتة للمحصول. يحفظ كقطة سعرية:

- `market_id` أو اسم السوق.
- المحصول والدرجة والوحدة.
- السعر والعملة.
- تاريخ ووقت السعر.
- نوع السعر: جملة، مفرق، عقد، مصنع، شراء من الحقل.
- مصدر السعر: إدخال المستخدم، مرشد، سجل فاتورة، مصدر خارجي.
- فترة صلاحية أو درجة الثقة.

### 4.7 البيع والتسويق

معاملة البيع ترتبط بدفعة إنتاج أو عدة دفعات:

- المشتري أو قناة البيع.
- تاريخ البيع.
- الكمية والدرجة والوحدة.
- السعر الوحدي والعملة.
- الخصومات والعمولة والنقل المحمل على البيع.
- صافي الإيراد.
- حالة التحصيل: غير محصل، جزئي، محصل.

## 6. مؤشرات الإنتاج والاقتصاد

### الإنتاج

```text
production_total = Σ harvested_quantity
marketable_production = Σ graded_quantity − Σ rejected_quantity
yield_per_area = marketable_production / area
loss_rate = rejected_quantity / harvested_quantity
```

### التكاليف

```text
total_cost = Σ actual_cost_entries
variable_cost = Σ costs المرتبطة مباشرة بالموسم
fixed_or_allocated_cost = تكاليف الآلات/الأرض حسب سياسة المستخدم
cost_per_area = total_cost / area
cost_per_marketable_unit = total_cost / marketable_production
```

#### تعريفات العرض المالي

- **التكلفة المباشرة**: تكلفة مرتبطة مباشرة بالموسم، مثل البذار والسماد والعمالة والنقل الخاص بالمحصول.
- **التكلفة الموزعة**: تكلفة مشتركة، مثل استخدام آلة أو أرض تخدم أكثر من موسم، وتحمّل حسب قاعدة معلنة مثل المساحة أو الساعات.
- **التكلفة التقديرية/الضمنية**: قيمة أدخلها المستخدم أو المرشد لأغراض التخطيط، ولا تعرض كتكلفة فعلية.
- **التكلفة المتغيرة**: تتغير مع حجم النشاط أو الإنتاج، وتضم عادة المدخلات والعمالة والخدمات والنقل المرتبط بالتنفيذ.
- **التكلفة الثابتة أو الموزعة**: تكلفة لا تتغير مباشرة مع كمية المحصول أو جرى توزيعها على الموسم وفق سياسة المستخدم. لا تدخل تلقائيًا في النسخة الأولى ما لم يحدد المستخدم طريقة التوزيع.
- **التكلفة الإجمالية**: مجموع السجلات الفعلية المؤهلة، مع فصل التكاليف المباشرة والموزعة والضمنية في العرض.

يجب أن يعرض التطبيق بجانب كل مؤشر: نوع البيانات المستخدم، العملة، وحدة المساحة، وفترة الحساب. وإذا وجدت عملات أو وحدات غير متجانسة، يعرض التحذير بدل جمعها تلقائيًا.

### الإيراد والربح

```text
gross_revenue = Σ(quantity × unit_price)
net_revenue = gross_revenue − selling_commission − transport_on_sale − other_sale_costs
net_margin = net_revenue − total_cost
margin_per_area = net_margin / area
break_even_price = total_cost / marketable_production
break_even_yield = total_cost / expected_unit_price
```

#### مؤشرات الأداء المالي بالتفصيل

1. **الإنتاجية القابلة للتسويق**: كمية المنتج القابلة للبيع مقسومة على المساحة. وهي المؤشر الزراعي الأساسي للمقارنة بين الحقول، بشرط توحيد الوحدة والمساحة.
2. **نسبة الفاقد**: الفاقد أو المرفوض مقسومًا على الإنتاج الخام. لا تساوي بالضرورة نسبة الدرجة الثانية؛ فالدرجة الثانية قد تكون قابلة للبيع بسعر مختلف.
3. **التكلفة الإجمالية للموسم**: مجموع `total_cost` للسجلات الفعلية غير الملغاة، مع إمكان عرضها في طبقتين: مباشرة وموزعة.
4. **التكلفة لكل وحدة مساحة**: التكلفة الإجمالية مقسومة على مساحة الموسم. تعرض مثلًا بالدونم أو الهكتار حسب الوحدة المختارة، ولا يجوز مقارنة نتيجتين بوحدتي مساحة مختلفتين دون تحويل.
5. **التكلفة لكل وحدة قابلة للتسويق**: التكلفة الإجمالية مقسومة على الكمية القابلة للتسويق. هذا المؤشر يتأثر بالفاقد والجودة، ولذلك يختلف عن تكلفة إنتاج الكيلو الخام.
6. **الإيراد الإجمالي**: مجموع كمية البيع مضروبة بالسعر الفعلي لكل معاملة، مع إبقاء الدرجة والعملة والتاريخ محفوظة.
7. **صافي الإيراد**: الإيراد الإجمالي ناقص العمولة والنقل والتعبئة والمصاريف المحملة على البيع. لا يطرح منه كامل تكاليف الإنتاج مرة ثانية في هذا المؤشر.
8. **صافي الهامش**: صافي الإيراد ناقص التكلفة المؤهلة وفق سياسة المستخدم. إذا استُخدمت التكاليف المباشرة فقط، يجب تسمية النتيجة بوضوح «هامش بعد التكاليف المباشرة».
9. **هامش الربح النسبي**: صافي الهامش مقسومًا على صافي الإيراد، ويعرض فقط عندما يكون صافي الإيراد موجبًا وغير صفري.
10. **سعر التعادل**: التكلفة المؤهلة مقسومة على الكمية القابلة للتسويق. هو السعر المتوسط الأدنى لتغطية التكلفة، وليس سعرًا سوقيًا أو توصية بيع.
11. **إنتاجية التعادل**: التكلفة المؤهلة مقسومة على سعر بيع مفترض أو فعلي لكل وحدة. لا تحسب عند غياب سعر موثق، ولا تستخدم سعر السوق التقديري كأنه سعر بيع فعلي.
12. **العائد على التكلفة**: صافي الهامش مقسومًا على التكلفة المؤهلة. يعرض مع وسم «تقديري» إذا كان الإنتاج أو السعر أو أي جزء من التكلفة تقديريًا.

#### قواعد المقارنة والتقدير

- قبل الحصاد، تستخدم المؤشرات الإنتاج المتوقع وسعرًا موثقًا أو مدخلًا تقديريًا، وتوسم صراحة بأنها **تقديرية**.
- بعد تسجيل الحصاد والبيع، تستخدم الكميات والأسعار الفعلية في المؤشرات الفعلية، مع إبقاء المقارنة مع الخطة الأصلية.
- لا يستبدل السجل الفعلي السجل المخطط؛ المقارنة المطلوبة هي: الفعلي ناقص المخطط، ونسبة الانحراف عندما تكون قيمة المخطط غير صفرية.
- عند غياب الإنتاج القابل للتسويق أو التكلفة أو السعر، تعرض قيمة `غير قابلة للحساب` بدل صفر.
- عند اختلاف العملة أو وحدة الكمية أو وحدة المساحة، لا تجمع السجلات حتى يحدد المستخدم تحويلًا ومصدره.
- تحليل الحساسية المستقبلي يغيّر متغيرًا واحدًا على الأقل، مثل السعر أو الإنتاج أو التكلفة، ويعرض نطاقًا لا توقعًا مؤكدًا.

عند غياب الإنتاج الفعلي، تعرض المؤشرات كتقديرية وتستخدم الإنتاج المتوقع. عند تسجيل الحصاد الفعلي، تعرض المقارنة بين التقديري والفعلي بدل استبدال السجل السابق.

## 7. حالات البيانات

كل سجل إنتاج أو تكلفة أو سعر يحمل `record_status`:

- `planned`: مخطط قبل التنفيذ.
- `actual`: حدث فعليًا وله مصدر أو إدخال مباشر.
- `estimated`: تقدير أدخله المستخدم أو المرشد.
- `cancelled`: ألغي ولا يدخل في المؤشرات.
- `superseded`: استبدل بتصحيح لاحق مع إبقاء الأثر التدقيقي.

## 8. سياسة النسخة HTML الحالية

النسخة الحالية تعمل محليًا داخل المتصفح، لذلك المرحلة الأولى من طبقة الإنتاج والتسويق ستكون:

- حفظ محلي مؤقت في `sessionStorage` أو ملف تصدير JSON.
- معرفات UUID أو معرفات زمنية محلية.
- عدم ادعاء أن البيانات مشتركة بين الأجهزة.
- زر تصدير واستيراد JSON قبل أي قاعدة خادمة.

عند الانتقال إلى backend تصبح الجداول علائقية مع API، ويصبح `field_id` و`season_id` مصدر الربط لكل السجلات.

## 9. مراحل التنفيذ

### المرحلة A — النموذج الأساسي

1. تعريف الموسم وخطة الإنتاج.
2. إضافة سجل التكاليف والعمليات.
3. إضافة سجل الحصاد والدفعات.
4. إضافة درجات الفرز والفاقد.

### المرحلة B — التسويق

1. أسعار السوق مع التاريخ والمصدر.
2. قنوات البيع والمشترون.
3. معاملات البيع وربطها بالدفعات.
4. صافي الإيراد والتحصيل.

### المرحلة C — التحليل الاقتصادي

1. مقارنة مخطط/فعلي.
2. ربحية الدونم والهكتار.
3. سعر التعادل وإنتاجية التعادل.
4. تحليل الحساسية للسعر والإنتاج والتكلفة.
5. مقارنة مواسم وحقول ومحاصيل.

## 10. حدود الإصدار الأول

- لا يجلب أسعارًا حية من السوق دون مصدر واتصال معتمد.
- لا يحسب الضرائب أو القروض أو الإهلاك المحاسبي الكامل.
- لا يعتبر التوقع الإنتاجي ضمانًا للمحصول.
- لا يخلط بين سعر المزرعة وسعر الجملة وسعر المفرق.
- لا يكتب توصية اقتصادية إذا كانت العملة أو الوحدة أو الإنتاج غير واضحة.
