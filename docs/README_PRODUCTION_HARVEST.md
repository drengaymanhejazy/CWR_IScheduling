# README — سجل الحصاد والإنتاج الخام

## الغرض

يسجل هذا المكوّن كل حدث حصاد مرتبطًا بالحقل والموسم والمحصول، ويفصل بين:

- الإنتاج الخام قبل الفرز.
- الكمية القابلة للتسويق عند إدخالها فعليًا.
- الفاقد أو المرفوض عند إدخاله فعليًا.

لا يحتوي هذا المكوّن على أسعار أو معاملات بيع أو درجات جودة تفصيلية؛ ستأتي هذه في مراحل لاحقة.

## الملف المحلي

```text
data/production_harvest_v0.1.json
```

وتحفظ الواجهة السجلات في المتصفح باستخدام:

```text
localStorage
المفتاح: cwr-production-harvest-v0.1
```

## دورة الاستخدام

1. يحدد المستخدم الحقل والموسم والمحصول من الإعدادات الحالية.
2. يضيف تاريخ حدث الحصاد.
3. يدخل الإنتاج الخام بوحدة محددة.
4. يدخل القابل للتسويق والفاقد إذا كانت الكميات معروفة؛ الفراغ يعني «غير معروف» وليس صفرًا.
5. يحدد الحالة: فعلي أو تقديري.
6. يحدد مصدر الكمية أو مرجعها.
7. يحفظ الحدث محليًا أو يصدّره إلى JSON.

## قواعد التحقق

- الإنتاج الخام إلزامي وأكبر من صفر.
- وحدة الكمية مشتركة للخام والقابل للتسويق والفاقد.
- لا يجوز أن يتجاوز مجموع القابل للتسويق والفاقد الإنتاج الخام إذا أُدخلا معًا.
- السجل التقديري لا يمثل كمية فعلية ولا يحل محل السجل الفعلي.
- السجلات الملغاة أو المستبدلة لا تدخل المؤشرات الحالية.
- لا يتم استنتاج القابل للتسويق أو الفاقد تلقائيًا عند عدم إدخالهما.
- لا توجد أسعار أو إيرادات في هذه المرحلة.

## المؤشرات الحالية

تعرض الواجهة للحقل والموسم الحاليين:

- مجموع الإنتاج الخام.
- مجموع الإنتاج القابل للتسويق، فقط للسجلات التي تحتوي هذه الكمية.
- مجموع الفاقد أو المرفوض، فقط للسجلات التي تحتوي هذه الكمية.
- الإنتاجية القابلة للتسويق لكل وحدة مساحة عندما تكون وحدة الكمية موحدة والمساحة معروفة.
- عدد أحداث الحصاد النشطة.

إذا اختلفت وحدات الكمية بين السجلات، تعرض الواجهة مجموعًا منفصلًا لكل وحدة بدل الجمع غير الصحيح.

## العلاقة مع الطبقات الأخرى

يستخدم سجل الحصاد هوية الحقل والموسم والمحصول نفسها المستخدمة في سجل العمليات والتكاليف. لكنه لا يغيّر:

```text
ET0 / Kc / ETc
ميزان ماء التربة
محرك SoilFert
```

لاحقًا يمكن ربط حدث الحصاد بدفعات الفرز والجودة، ثم بمعاملات البيع، دون حذف كمية الإنتاج الخام الأصلية.

## التصدير والاستيراد

تصدّر الواجهة سجلات الحقل والموسم الحاليين في بنية:

```json
{
  "schema_version": "production_harvest_v0.1",
  "record_type": "harvest_events",
  "identity": {},
  "records": []
}
```

عند الاستيراد، تقبل الواجهة السجلات التي تطابق `field_id` و`season_id` الحاليين فقط، لتجنب خلط مواسم أو حقول مختلفة.
